# ХаткоБот: перша лінія підтримки

Станом на 2026-10-12 застосунок використовує Laravel 13.35, Laravel AI SDK 1.2, Laravel Boost 2.10 та Laravel MCP 1.0. API чату доступне авторизованим користувачам через `POST /help/ask`; ним користуються сторінка `/help` і віджет.

## Стратегія відповіді

1. Прості привітання обробляються локально. Запити про можливості застосунку надходять до `HelpAssistant`, окремого SDK `Agent` з `Promptable`, `HasTools` і `RemembersConversations`.
2. Перший крок агента обов’язково викликає read-only SDK tool `SearchSupportKnowledge`. Інструмент передає запит до `DocumentRetriever`: embeddings `openai/text-embedding-3-small`, PostgreSQL/pgvector, максимум п’ять фрагментів із дозволених `docs/user_docs/*.md`. Поріг подібності налаштовується через `AI_SUPPORT_MIN_SIMILARITY`.
3. Агент відповідає українською за знайденими фрагментами. Джерела для карток посилань сервер бере лише з успішних результатів інструмента і звіряє з `config/ai-support.php`. Посилання, написані самою моделлю, не є джерелами.
4. Якщо ключ відсутній, провайдер недоступний, результат порожній або відповідь не має перевіреного джерела, спрацьовує локальний `AssistantResponder`. Агент не читає персональні показання чи витрати і не змінює дані.

Промпт, вміст документа та історія розмови не логуються. Один запит має щонайбільше три кроки генерації і 500 вихідних токенів. Ліміти: 6 запитів за хвилину і 100 за добу на користувача; паралельні AI-запити того самого користувача повертають HTTP 429.

## Контракт чату та історія

Запит: `{ "question": "Як внести показання?", "conversation_id": "<необов’язковий UUID>" }`.

Відповідь: `{ "text": "...", "sources": [{"label": "Показання", "path": "/readings"}], "conversation_id": "<UUID або null>" }`.

SDK зберігає розмови на сервері. Перш ніж продовжити розмову за надісланим UUID, застосунок перевіряє її власника через `VerifiesConversationOwnership`; чужий або невідомий UUID дає HTTP 403. Віджет зберігає UUID лише у поточному стані сторінки, очищає його кнопкою нової розмови та скасовує запит, відповідь на який уже не потрібна. Після перезавантаження сторінки починається новий видимий чат. Після видалення акаунта його збережені розмови та повідомлення видаляються.

Запит і відповідь передаються OpenRouter, тому користувач не повинен надсилати паролі, коди підтвердження або платіжні реквізити.

## Запуск і оновлення

1. Використовувати PHP 8.4+, PostgreSQL 17 із pgvector і Redis. Локальний та production Compose налаштовано на образ `pgvector/pgvector:0.8.5-pg17-trixie`.
2. Встановити `OPENROUTER_API_KEY`. За потреби задати `AI_SUPPORT_MODEL`, `AI_SUPPORT_EMBEDDING_MODEL`, `AI_SUPPORT_MIN_SIMILARITY` та `AI_SUPPORT_MAX_CHUNKS` (від 1 до 5). Індексатор і пошук використовують одну embedding-модель; при її зміні повторний запуск команди перестворює несумісні вектори. До завершення переіндексації пошук не змішує вектори різних моделей.
   `AI_SUPPORT_MODEL` має приймати зображення та підтримувати виклик інструментів; моделі OpenRouter з суфіксом `:free` працюють на спільному upstream-ліміті запитів (429), тому не підходять для розпізнавання фото.
3. У контейнері виконати `php artisan migrate --force`, потім `php artisan ai:rag:ingest docs/user_docs --prune`. Індексація нових або змінених фрагментів викликає платний API embeddings. Вже незмінені вектори використовуються повторно.
4. Перевірити українські запити на реальному індексі й відкалібрувати поріг подібності. Без ключа або наповненого індексу працюють лише локальні шаблонні відповіді.

Міграція історії підтримує нові інсталяції та вже застосовану схему AI SDK 0.9. Перед production-розгортанням потрібна резервна копія БД. Live-виклик OpenRouter та якість кросмовного пошуку не підтверджені локальними тестами з fake-провайдером.
