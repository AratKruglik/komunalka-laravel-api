# ХаткоБот: маршрутизація та підтримка

Серверний код ХаткоБота розташований у `Modules/Ai`. Для авторизованого користувача доступні `POST /help/ask`, `POST /help/approve` і `GET /help/state`; інтерфейс використовує один публічний `conversation_id`.

## Маршрутизація

Нове фото та уточнення до активного фото надходять безпосередньо до `MeterReadingAgent`. Активна чернетка налаштування продовжується `PropertySetupAgent`. Для нового тексту `ClassifyHelpIntent` викликає TypeSafe Jev через Laravel AI SDK Classification і повертає один із чотирьох типізованих намірів: `meter_reading`, `property_setup`, `product_support`, `clarify`. Сервер сам зіставляє намір із класом агента. Класифікатор не отримує фото, повної історії чи персональних ID.

Автоматичний текстовий маршрут запускається лише після налаштування `AI_ROUTER_MIN_PROBABILITY` та `AI_ROUTER_MIN_MARGIN`. За відсутності порогів або при некоректній відповіді Jev працює локальна довідкова відповідь чи уточнення; створення сутностей не починається. Привітання обробляється без AI-виклику.

## Агенти та підтвердження

- `ProductSupportAgent` має лише `SearchSupportKnowledge`. Документи беруться з `docs/user_docs`, а посилання у відповіді сервер звіряє з `config/ai-support.php`.
- `MeterReadingAgent` має список власних лічильників і інструмент пропозиції показання. Фото зберігається на приватному диску після видалення метаданих. Показання записується лише після підтвердження картки.
- `PropertySetupAgent` читає обмежені довідники й власні адреси, провайдерів та лічильники. Його інструмент змінює лише серверну чернетку. Повний пакет адреси, провайдера та лічильника записується в одній транзакції після підтвердження. Тарифи додаються тільки на явний запит.

Нові пропозиції зберігаються у `help_approvals` з версією, строком дії та одноразовим результатом. Повторне підтвердження вже застосованої пропозиції повертає той самий результат. Старі відкриті SDK-розмови та approval ID проходять через адаптер сумісності.

Публічна розмова належить одному користувачу; внутрішні SDK ID сервер тримає у `help_conversations.agent_conversation_ids` і не передає клієнту. Віджет зберігає публічний ID у браузері та після перезавантаження відновлює активну картку через `GET /help/state`. Повний видимий журнал повідомлень не відновлюється.

## Запуск

1. Установити `OPENROUTER_API_KEY`; за потреби задати `AI_SUPPORT_MODEL`, `AI_METER_MODEL`, `AI_SETUP_MODEL`, `AI_ROUTER_MODEL`.
2. Після перевірки Jev на розмічених українських запитах задати `AI_ROUTER_MIN_PROBABILITY` і `AI_ROUTER_MIN_MARGIN`. Без них новий текстовий намір безпечно уточнюється.
3. Виконати `php artisan migrate --force` і `php artisan ai:rag:ingest docs/user_docs --prune` у контейнері. Індексація викликає платний embeddings API; без індексу довідковий агент використовує локальну відповідь.

Запити та очищені фото передаються OpenRouter. Не надсилайте паролі, коди підтвердження або платіжні реквізити. Повна схема й алгоритм описані в [архітектурі](hatkobot-multi-agent-architecture.md).
